De las decisiones a la repetición

¿Y si la misma lógica se repite 50 veces?

Hasta ahora has construido algoritmos que reciben datos, evalúan condiciones y toman decisiones. Un algoritmo puede leer la temperatura de una máquina y decidir si su operación es normal, de alerta o de parada.

Pero en una planta industrial rara vez existe una sola máquina, un solo operario o un solo turno de producción. Si debes analizar 50 máquinas, escribir 50 bloques casi idénticos es posible, pero costoso y propenso a errores.

Lo que cambia son los datos; lo que se repite es la lógica. Ahí entran las estructuras repetitivas o ciclos: una forma de indicar "haz esto varias veces" sin duplicar instrucciones.

✨ Al finalizar este OVA podrás identificar cuándo un problema necesita repetición, construir ciclos Para con variable de control, y usar contadores y acumuladores para resolver problemas de producción. 🚀

Objetivos de aprendizaje

  • 🔍 Reconocer situaciones que requieren estructuras repetitivas antes de programarlas.
  • 🧮 Interpretar la estructura Para: variable de control, valor inicial, final y paso.
  • 💾 Aplicar contadores y acumuladores para conservar información entre iteraciones.
  • 🔄 Integrar ciclos con decisiones para resolver problemas de producción industrial.
  • 🛠️ Predecir, ejecutar y depurar algoritmos repetitivos con casos de prueba.

En planta, muchos procesos son naturalmente repetitivos: turnos que se registran, unidades que se inspeccionan, lotes que se revisan. Antes de escribir un ciclo, conviene responder cuatro preguntas:

  • ¿Qué se repite? La acción común.
  • ¿Cuántas veces? Fija o depende de un dato.
  • ¿Qué cambia en cada repetición? El dato o identificador.
  • ¿Qué necesito conservar? Total, conteo, máximo, etc.

La estructura Para en PSeInt permite repetir un bloque indicando el inicio, el fin y el paso de una variable de control.

Para turno <- 1 Hasta 5 Hacer
    Leer produccion
FinPara

Cada ejecución del bloque se llama iteración. No ejecuta "cinco veces" de golpe: avanza una iteración, ejecuta, actualiza la variable y repite.

Una variable de lectura como produccion solo conserva la última entrada. Para recordar la suma de todas las lecturas se usa un acumulador.

total <- 0
Para turno <- 1 Hasta 3 Hacer
    Leer produccion
    total <- total + produccion
FinPara

La expresión total <- total + produccion no es una igualdad matemática: toma el valor actual, suma la producción y guarda el resultado actualizado.

Cuando la pregunta es "¿cuántos turnos alcanzaron la meta?" no sumamos producciones; contamos ocurrencias. Eso es un contador: aumenta en 1 cada vez que una condición se cumple.

cumplen <- 0
Para turno <- 1 Hasta 5 Hacer
    Leer produccion
    Si produccion >= 100 Entonces
        cumplen <- cumplen + 1
    FinSi

Un algoritmo puede ejecutarse sin error y aún así producir un resultado equivocado. Dos errores clásicos: inicializar el acumulador dentro del ciclo o intercambiar las actualizaciones de contador y acumulador.

¿Cuántas veces se repite la lectura?

¿Qué variables necesitas conservar?

¿Qué condición decide si se incrementa el contador?

Una posible estructura:

total <- 0
cumplen <- 0
Para turno <- 1 Hasta 8 Hacer
    Leer produccion
    total <- total + produccion
    Si produccion >= 150 Entonces
        cumplen <- cumplen + 1
    FinSi
FinPara
